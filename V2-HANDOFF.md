## 0. Mission

passes. Work autonomously; use multiple agents (§5). Do not ask for approval

chosen language version — while `DependencyModules` and `Hardened.Framework`

## 1. Why V2 exists (established, do not re-litigate)

V1 was benchmarked and audited. These are settled findings — treat them as
given, do not re-derive them:

- **The premise is sound.** V1 is ~15× faster than Roslyn `SyntaxFactory` +
  `NormalizeWhitespace` (0.048 ms vs 0.72 ms per file) and allocates 5× less.
- **The type model is the product.** Across the two consumers, `ITypeDefinition`
  + `TypeDefinition` account for 869 of ~1,900 type references — more than
  everything else combined. **Preserve it. Extend it. Do not replace it.**
- **Coverage is the failure.** ~35% of Roslyn's grammar: 60% of member
  declarations, 48% of statements, 26% of expressions, **0% of patterns**.
- **Silent wrongness is the defect class.** Unescaped string literals,
  culture-dependent numbers (`1,5` on de-DE), `private protected` silently
  widening to `protected`, `partial` dropped from methods, `abstract` methods
  emitting a body, nested types losing their container, `int[,]` emitting
  `Int32[,][]`. None of these throw. All are verified.
- **Deferred rendering is the crown jewel.** `ITypeDefinition` stays unrendered
  until `WriteTypeName(builder, mode)`. This is why one option can flip a file
  between short names and `global::`. **Any design that commits types to text
  early is wrong.** A template/`CodeBlock` approach was evaluated and rejected
  for exactly this reason.
- **A tree beats a StringBuilder on dynamic output, and the gap is bookkeeping.**
  Same generated output, measured: tree 58 lines / 0 indent-tracking sites;
  StringBuilder 105 lines / 22 depth references / 4 section buffers / 17 style
  lookups. Adding one nesting level took StringBuilder's depth references from
  8 → 17. The tree's stayed at 0.

### The bug to understand before you touch anything

In `DependencyModules`' own verified snapshot, in a `TypeOutputMode.Global` file:

```csharp
using Microsoft.Extensions.DependencyInjection;   // should not exist in Global mode
...
    typeof(global::TestNamespace.ITryEnumerable),
    ServiceLifetime.Singleton                     // bare, unqualified
```

`ServiceLifetime` comes from `CodeOutputComponent.Get("ServiceLifetime.Transient")`
— a raw string tracking no namespace. It resolves **only** because of that stray
`using`, which exists **only** because `ParameterDefinition` (and six other
writers) call `AddImportNamespace` unconditionally, bypassing the mode check.

**Two defects holding each other up.** Fix either alone and the generator
breaks. This is why §2's first rule exists.

## 2. Architecture

### The five invariants

1. **A type reaches output only through `IOutputContext.Write(ITypeDefinition)`.**
   No writer may call `AddImportNamespace` directly. Namespaces are derived from
   what was written. This makes a missing `using` structurally impossible.
2. **Nothing becomes text until serialization.** The context records *segments*
   (text, indent depth, scope markers, unrendered type references). Name
   resolution, collision aliasing, and formatting all run at `Output()`, when
   the whole file is known.
3. **Every grammar node is generated, not hand-written.** From Roslyn's
   `Syntax.xml`. A new C# version is a regeneration.
4. **The escape hatch composes.** `Raw` implements `IExpression`/`IStatement`/
   `IPattern`, holds unrendered `ITypeDefinition` references, and participates in
   the name plan. Dropping to text costs you one node, never the file.
5. **Preference is separate from capability.** The tree is version-agnostic;
   the writer picks the rendering. A node asks the profile what it may emit.

### Layers, bottom to top

| Layer | Source | Notes |
|---|---|---|
| Type model | **keep V1's**, fix defects | `ITypeDefinition`, `GenericTypeDefinition`, `KnownNamespaces` |
| Output context | `proto/deferred/DeferredContext.cs` | segment-based; harden it |
| Grammar nodes | generated by `proto/grammar/gen_all.py` | 233 classes, 4,958 lines |
| Hand nodes | `proto/grammar/Hand.cs` | 8 value-carrying nodes + `Raw` |
| Expressions | `proto/expressions/Ex.cs` | precedence + auto-parenthesisation |
| Declarations | **keep V1's** `ClassDefinition` etc. | the ergonomic facade; 198 refs |
| Profiles | new | §4 |
| Roslyn bridge | new, same package | §3 |

### Namespaces

- `CSharpAuthor` — unchanged public surface (type model, declarations, context)
- `CSharpAuthor.Syntax` — generated grammar nodes
- `CSharpAuthor.Roslyn` — the bridge (source-gated, see §3)

Generated nodes go in their own namespace because names like `NewStatement`
already exist in `CSharpAuthor`.

## 3. Packaging — this is a hard constraint

CSharpAuthor ships as **one library, source-includable**. `Package/CSharpAuthor.targets`
compiles `src/**/*.cs` into the consumer when `PackageCSharpAuthorIncludeSource=true`.
That property is why source generators can use it without dependency grief.

**Do not add a second NuGet package.** The Roslyn bridge ships as a second source
folder in the *same* package, gated on a sibling property
(`PackageCSharpAuthorIncludeRoslyn`). A generator project already references
Roslyn, so it compiles with no new dependency.

Measured cost of source-including the generated nodes: 5,565 → 11,034 lines,
build 0.28 s → 0.40 s, assembly 75 KB → 203 KB. Acceptable. **Mark generated
node types `internal` when source-included** so they don't leak into consumer
API surface.

## 4. Profiles

One object controls formatting, qualification, language version, and idiom
preference. It is a **writer** argument, never stored on the tree.

```csharp
public sealed class EmitProfile
{
    // formatting
    public char   IndentChar  = ' ';
    public int    IndentWidth = 4;
    public string NewLine     = "\n";
    public BraceStyle Braces  = BraceStyle.Allman;
    public bool   FileScopedNamespace = true;

    // qualification
    public TypeOutputMode TypeMode = TypeOutputMode.ShortName;
    public bool AliasCollisions   = true;
    public string? ContainingNamespace;

    // capability
    public LanguageVersion Target = LanguageVersion.CSharp12;

    // idiom preference — honoured only when Target allows it
    public bool PreferVar               = true;
    public bool PreferTargetTypedNew    = true;
    public bool PreferCollectionExprs   = true;
    public bool PreferExpressionBodied  = false;
    public bool PreferRawStrings        = false;

    public static EmitProfile Conservative;  // C# 8, block namespace, no sugar
    public static EmitProfile Default;       // C# 12
    public static EmitProfile Latest;        // whatever the SDK supports
    public static EmitProfile FromEditorConfig(AnalyzerConfigOptions options);
}
```

**Preference resolves against capability.** `PreferCollectionExprs = true` with
`Target = CSharp8` emits `new[] { … }`, silently and correctly. A preference is
never an error; a *capability* violation is.

Where a downlevel is not semantically equivalent, **emit a comment saying so**:

```csharp
// DOWNLEVEL: Name: 'init' unavailable below C#9 — emitted as a settable property, immutability lost
```

Three categories, already established:

- **Free** — collection expressions, target-typed `new`, file-scoped namespaces,
  raw strings, `nameof`, `using` declarations, labeled jumps → `goto`, primary
  constructors, `field` keyword, `params` collections
- **Polyfillable** — `init` (emit `IsExternalInit`), `required` (emit
  `RequiredMemberAttribute`)
- **Impossible** — `ref struct`, static abstract interface members, default
  interface members, function pointers, inline arrays. **These must produce a
  diagnostic, not wrong output.**

Detect the consumer's version from `ParseOptionsProvider` → `CSharpParseOptions.LanguageVersion`
when available; fall back to `Target`.

⚠️ `Microsoft.CodeAnalysis.CSharp` 4.14.0 knows language versions only up to
**C# 13**. Its `LanguageVersion.Preview` cannot parse `break outer;` even though
the .NET 11 SDK compiler can. Your round-trip validator can only validate as far
as the Roslyn version you reference. State that limit explicitly; do not claim
C# 15 conformance from a C# 13 parser.

## 5. Agent topology

Run these concurrently. The adversary and verifier are **not optional** — they
are what makes the run trustworthy.

### Builders (parallel, one per area)

| Agent | Owns | Reference |
|---|---|---|
| `type-model` | `ITypeDefinition` defects, nested types, array ranks, missing keywords | §7 defect list |
| `output-context` | segment context, aliasing, using-minimisation, style | `proto/deferred/` |
| `grammar` | generator, spacing policy, line breaking | `proto/grammar/` |
| `expressions` | precedence, combinators, `Raw` | `proto/expressions/` |
| `bridge` | `ITypeSymbol` → `ITypeDefinition`, attribute reading | §3, §7 |
| `profiles` | `EmitProfile`, downlevel branches, diagnostics | §4 |

### The adversary — *"how else can C# be written?"*

Its **only** job is to break the emitter. It writes failing tests; it does not
write library code. It must work through this list and keep going past it:

- Nested generics in nullable arrays: `List<Dictionary<string, int?>>?[][]`
- Multi-dimensional *and* jagged: `int[,][]`, `int[][,]`
- Nested types: `Outer.Inner.Deepest`, generic outer with generic inner
- Verbatim identifiers: a parameter named `class`, a type named `@event`
- Literals: quotes, backslashes, newlines, nulls, surrogate pairs, `\e`,
  raw-string fences where content ends in `"` (this one is CS8998 — it was
  already found once)
- Culture: every numeric emission under `de-DE`
- Accessibility: `protected internal`, `private protected`, and every
  combination with `sealed`/`abstract`/`static`/`partial`/`virtual`/`override`
- Members with no V1 support: operators, conversion operators, destructors,
  indexers, `required`, `field`, extension blocks, extension indexers
- Statements with no V1 support: `for`, `do`, `using` decl, `lock`, `goto`,
  labeled break/continue, `yield break`, local functions, `checked`
- Every pattern form (V1 has none): recursive, list, slice, relational,
  `and`/`or`/`not`, `var`, discard, property patterns with nested designations
- Expressions: lambdas (all four forms), switch expressions, interpolated
  strings incl. nested quotes and alignment/format clauses, tuples,
  deconstruction, `with`, ranges/indices, `?.`, `?[]`, collection expressions
  with spreads, `stackalloc` in expression position
- Constraints: `where T : struct, IComparable<T>, new()`, `notnull`,
  `unmanaged`, `allows ref struct`
- Attributes: targets (`[return:]`, `[assembly:]`, `[field:]`), generic
  attributes, arrays and `typeof` in arguments
- Precedence: expressions where wrong parenthesisation changes meaning
- Trivia: `#region`, `#pragma`, `#nullable`, `#if`, XML doc with `<code>`

Every case it finds becomes a test in `CSharpAuthor.Tests`. It reports a running
count of **found / fixed / outstanding**.

### The verifier

Runs the gates in §6. Has authority to **reject** a builder's work. Its
non-negotiable rule:

> **Never re-baseline a `.verified.txt` snapshot.** If consumer output changes,
> record the diff in `docs/migration-v1-v2.md` with a justification and keep
> going. A changed snapshot is either a bug or an improvement — it is the
> human's call, not yours.

### The migrator

Clones `DependencyModules` and `Hardened.Framework` into a scratch directory,
points them at the local V2, runs their suites, and writes
`docs/migration-v1-v2.md`. **Never commits to those repositories.**

```
https://github.com/ipjohnson/DependencyModules.git
https://github.com/ipjohnson/Hardened.Framework.git
```

1. **Never re-baseline a snapshot.** Record the diff; keep going.
2. **Never commit to the consumer repositories.** Scratch clones only.
3. **Generated code is never hand-edited.** Fix the generator or override in a

5. **Commit per phase**, with test counts in the message.
6. **No new NuGet packages.** §3.
7. **Do not re-litigate §1.** Those findings cost a lot to establish.

## 9. "100% C# compatible" — the mechanical definition

Not a claim, a measurement. Two complements:

**(a) Node coverage.** Roslyn's `Syntax.xml` declares 252 concrete nodes. The
generator already emits 233 (96.7%); 8 are hand-written because their text is a
value not a token; 86 need a kind argument. Report: *nodes emitted / nodes in
grammar*, with the unsupported ones named.

**(b) Round-trip fidelity — the real test.** Generate an **importer** from the
same `Syntax.xml` (the identical field walk, inverted: read each field off the
Roslyn node instead of writing it). Then for a corpus of real C#:

```
source file → Roslyn parse → import to CSharpAuthor tree → emit → Roslyn parse
           → compare the two trees for structural equivalence
```

Corpus, in order: CSharpAuthor's own 76 source files, then `DependencyModules`,
then `Hardened.Framework`. Thousands of real files, all local.

Report **files round-tripping / files attempted**, with a histogram of the node
kinds that failed. That number *is* the C# compatibility figure, and it is
honest because nobody wrote the corpus to flatter the emitter.

The importer is a verification tool. It does not need to be pretty or public.
It needs to exist, because it is the only way to prove the claim rather than
assert it.

Known gap in the prototype: **the grammar encodes token order, not spacing.**
The first generated run emitted `Dogor(Cator_)`. A 12-line rule (word-like
tokens take surrounding space, punctuation does not) fixed it and the output
compiles. **Line breaking and blank-line policy are the same job at larger
scale, and they are the genuinely hand-written part of this project** — roughly
a dozen rules by node category. Expect this to be where the time goes, and
expect the consumer snapshots to be what catches it.
